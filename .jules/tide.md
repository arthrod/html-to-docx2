## 2024-05-24 - Unit Conversion Pure Functions
**Learning:** Pure functions like the unit conversion utilities in `src/utils/unit-conversion.ts` are ideal for Tier 1 testing. They require zero mocking, run extremely fast, and are fundamental for preventing downstream regressions in complex calculations (like line heights or image dimensions).
**Action:** Always prioritize finding and testing pure, math-heavy utilities before tackling complex, mock-heavy UI or network interactions, as they offer the highest signal-to-noise ratio in tests.

## 2024-06-20 - Testing SSRF IPv4 Single Integer Validation Edge Cases
**Learning:** When writing tests to protect against Server-Side Request Forgery (SSRF) bypasses where an attacker encodes IP addresses as single integers, it is surprisingly easy to write a false-green test or miss critical edge cases. Because JavaScript's bitwise right shift operator (`>>>`) converts values into 32-bit *unsigned* integers for the calculation, passing a *signed* 32-bit integer that represents a high IPv4 address (like `192.168.1.1` as `-1062731519` or `169.254.169.254` as `-1442971138`) causes it to be seamlessly converted under the hood, correctly extracting the octets. If a test suite doesn't explicitly pass negative strings when validating IPv4 integers in bitwise pipelines, you're missing coverage for common SSRF fuzzing vectors that attackers utilize to obscure local IP targets.
**Action:** When testing SSRF validation utilities that evaluate IP addresses via bitwise integer math, ensure that high-order octet IPs (e.g. Class C private `192.x.x.x` and Link-Local `169.254.x.x`) are tested by explicitly providing their *negative* signed 32-bit integer equivalents.
